File analysis

What a file hash can tell you

Two text files look identical in an editor. SpireAV gives them different fingerprints. The difference comes down to one byte.

Tokyo09   /   25 Nov 2026

Open two plain-text files. Each contains the word hello followed by a single line break. Put the cursors at the ends of the files and both land on an empty second line. Where does the extra byte come from?

One line break, two fingerprints

Save both files as UTF-8 without a byte-order mark. Give the first a Unix line ending (LF) and the second a Windows line ending (CRLF). The second file uses two bytes to signal the end of the line. Here are the first eight hexadecimal characters of each SHA-256 digest.

EndingSizeSHA-256 prefix
LF6 bytes5891b5b5
CRLF7 bytescd2eca35

SpireAV’s hashing module reads a file in blocks of 8,192 bytes and feeds each block to both MD5 and SHA-256. The filename never enters that calculation. If two scan reports use different filenames, comparing the full SHA-256 values can help you identify copies with the same contents.

What a rule adds

SpireAV also supports YARA rules, which describe patterns to look for in files. Imagine a rule whose only condition is the presence of the bytes for hello. Both files would match. In this example the match tells you that each file contains a greeting. The hashes let you tell the two copies apart.

Read the SpireAV hashing module and the project README.
